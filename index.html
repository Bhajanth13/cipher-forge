Step 1 of 7 Module 1: sets

Choose the symbols

Every cipher works on a set S of symbols. Its size, the cardinality |S|, decides everything that follows: how arrows are drawn, which blocks are safe, and how many keys exist.

Step 2 of 7 Module 3: functions and composition

Build a cipher from blocks

Each block is a function f : S → S. Blocks run left to right, so a chain f₁ then f₂ is the composition f₂ ∘ f₁.

    Do the brackets matter?

    A chain of k blocks can be bracketed in Cₖ₋₁ ways, the Catalan number Cₙ = C(2n, n) / (n + 1). Composition is associative, so every bracketing gives the same cipher.

    Step 3 of 7 Modules 2 and 3: logic, bijections, pigeonhole

    Check that it can be undone

    A cipher can be decrypted only if its function is a bijection: one-to-one and onto. The arrow diagram shows the function. Pick f₂ ∘ f₁, f₃ ∘ f₂ ∘ f₁ and so on to watch your blocks build F one step at a time; tap a symbol to pin its path.

    One-to-one

    ∀x₁, x₂ ∈ S : f(x₁) = f(x₂) → x₁ = x₂

    Onto

    ∀y ∈ S ∃x ∈ S : f(x) = y

    Pigeonhole

    The validity rule as a proposition

    Let I = “f is one-to-one”, O = “f is onto”, V = “f can be decrypted”. Then V ⇔ I ∧ O. The highlighted row is the function above.

    Because S is finite and mapped to itself, I and O are logically equivalent here (I ⇔ O), so only the first and last rows can ever occur.

    Step 4 of 7 Modules 1 and 3: Cartesian product and relations

    See the cipher as a relation

    A function is a special relation: a set of ordered pairs R = { (x, f(x)) } inside S × S. Drawn as a grid, a function has exactly one dot in every row, and a bijection also has exactly one dot in every column.

        Step 7 of 7 Modules 4 and 5: counting

        Count the keys an attacker must try

        A brute-force attacker tries every key. The sum rule, product rule, permutations and combinations tell us how many there are. Counts are exact, computed with BigInt.
