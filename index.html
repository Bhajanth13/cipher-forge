Step 1 of 5 Module 1: sets

Choose the symbols

Every cipher works on a set S of symbols. Its size, the cardinality |S|, decides everything that follows: how arrows are drawn, which blocks are safe, and how many keys exist.

    Step 3 of 5 Modules 2 and 3: logic, bijections, pigeonhole

    Check that it can be undone

    A cipher can be decrypted only if its function is a bijection: one-to-one and onto. The arrow diagram shows the function; hover a symbol to trace its arrow.

    One-to-one

    ∀x₁, x₂ ∈ S : f(x₁) = f(x₂) → x₁ = x₂

    Onto

    ∀y ∈ S ∃x ∈ S : f(x) = y

    Pigeonhole

    The validity rule as a proposition

    Let I = “f is one-to-one”, O = “f is onto”, V = “f can be decrypted”. Then V ⇔ I ∧ O. The highlighted row is the function above.

    Because S is finite and mapped to itself, I and O are logically equivalent here (I ⇔ O), so only the first and last rows can ever occur.

    Step 4 of 5 Module 3: inverse of a composition

    Encrypt, then undo it

    Encryption applies every block in order. Decryption applies each inverse in reverse order, because (g ∘ f)⁻¹ = f⁻¹ ∘ g⁻¹. Symbols outside S pass through unchanged.

    Step 5 of 5 Modules 4 and 5: counting

    Count the keys an attacker must try

    A brute-force attacker tries every key. The sum rule, product rule, permutations and combinations tell us how many there are. Counts are exact, computed with BigInt.

    Password symbols (sum rule)

    Key typeRuleNumber of keysTime to try them all

    A huge key count is necessary but not enough. Substitution ciphers have n! keys, yet letter-frequency counting still breaks them: any message longer than |S| must repeat a symbol, by the pigeonhole principle.
